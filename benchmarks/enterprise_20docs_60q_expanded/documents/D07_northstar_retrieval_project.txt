北极星检索平台是集团统一检索基础设施，主要面向知识片段、项目资料和企业内部文档提供语义检索能力。平台负责接收经过处理的文本片段，构建向量索引，并在问答或其他上层应用需要时返回相关检索结果。北极星属于检索基础设施，不承担完整的客户门户、用户鉴权或 API 网关职责，因此在分析系统边界时需要将“检索能力”和“接入能力”“权限能力”分开。

陈航负责北极星检索平台。作为项目负责人，他负责检索链路、索引工程和相关问题排查，并与数据平台部内的数据工作协同。陈航同时是数据平台部的数据工程师，但项目责任与部门归属属于不同关系：前者说明他负责哪个项目，后者说明他属于哪个组织。北极星的其他上下游服务也各有独立负责人，不能从项目依赖关系反向推断负责人。

北极星当前向量检索存储使用 Chroma，通过语义向量完成知识片段召回。系统会保存与文档和版本相关的元数据，以便检索结果能够追溯到具体来源。技术评审中可以讨论其他向量数据库或后续优化方案，但当前知识库明确记录的运行方案仍是 Chroma。遇到“当前使用什么”和“曾经评估什么”的问题时，应优先依据明确的当前状态描述。

为了保持索引更新及时，北极星依赖 Atlas 事件服务获取文档变更事件。Atlas 提供事件分发能力，北极星消费这些事件后触发相应索引更新流程。这个关系表示“北极星依赖 Atlas”，并不表示 Atlas 依赖北极星，也不表示 Atlas 的负责人就是北极星负责人。北极星还会向天枢知识平台提供检索索引，这是另一个方向不同的关系。

北极星本身不负责客户门户认证，也不直接承担 API 网关职责。客户认证由猎户座权限服务承担，外部 HTTP 接入和路由由云桥 API 网关承担。若问答系统需要跨文档判断北极星与这些系统的关系，应保持职责和方向准确。本文件也不记录北极星的日活用户数和正式上线日期，因此这类问题不能通过现有资料回答。

北极星相关问答还应区分项目责任、当前技术和上下游关系三类证据。一个问题可能同时命中陈航、Chroma、Atlas、天枢等实体，但只有与问题语义直接相关的关系才能进入最终结论，不能把同一文档中的共现实体自动连成新关系。

检索平台在日常运行中可能同时出现索引更新、查询召回、事件消费和上层调用等多类日志。知识问答只应使用经过文档确认的架构关系，不从日志共现推断新的依赖。这样可以让北极星在复杂语料中仍保持清晰的负责人、技术和上下游边界。
