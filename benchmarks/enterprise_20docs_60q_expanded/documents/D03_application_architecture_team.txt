应用架构部负责集团共享服务、接口治理和平台架构，是多个业务系统之间进行能力复用和接口协同的重要部门。部门工作通常包括 API 接入规范、共享服务设计、接口边界评审以及跨系统依赖梳理。应用架构部会与数据平台部、安全运营部和客户成功部合作，但协作本身不改变人员归属，也不意味着应用架构部负责所有被它支持的业务项目。

赵启是应用架构部负责人，承担部门资源协调与平台架构方向的管理职责，同时负责 Atlas 事件服务方向。Atlas 是集团内部事件分发服务，为需要感知文档变化的系统提供事件能力。赵启作为 Atlas 的负责人，与他作为应用架构部负责人的身份可以同时成立，但这两个关系不能反向推出他负责所有依赖 Atlas 的项目。例如北极星检索平台依赖 Atlas，并不意味着赵启就是北极星负责人。

魏衡是平台架构师，隶属应用架构部，主要负责 API 网关与服务接入规范。他关注对外接口统一、路由治理以及平台服务之间的接入约束。魏衡负责的云桥 API 网关属于共享接入能力，和赵启负责的 Atlas 事件服务职责不同：前者处理 HTTP 接入与路由，后者处理事件分发。二者都属于应用架构相关能力，但不能因为同处一个部门就把服务职责合并。

应用架构部与数据平台部在天枢知识平台上存在明确协作。天枢由两个部门共同交付，因此在组织和项目关系查询时，既可能出现“应用架构部 SUPPORTS 天枢”一类支持关系，也可能出现赵启作为共同负责人参与天枢的项目关系。需要区分“部门支持项目”“个人共同负责项目”和“个人属于部门”这三种不同层次的事实。

本文件用于支持人员与部门、部门与项目协作等查询。赵启和魏衡都与应用架构部有关，但一个是部门负责人，一个是平台架构师。文档没有把陈航、唐悦、方屿等其他部门成员归入应用架构部。若问题要求判断负责 Atlas 与负责云桥的人是否来自同一部门，应结合 Atlas 和云桥的具体项目文档以及本文件中的人员归属信息。

当应用架构部同时出现在 Atlas、云桥和天枢等文档中时，检索系统需要依赖具体实体和谓词完成消歧。赵启负责 Atlas，魏衡负责云桥，二人都与应用架构部相关，但服务对象与技术职责不同；共同部门背景不能覆盖这些更细粒度的责任事实。

这类跨文档组合查询能够检验系统是否真正利用组织关系与服务责任，而不是仅依赖单段文本中的表面相似度。

因此服务职责和组织归属必须分别取证，避免同部门实体之间被自动建立错误业务边。
